# Failure modes

**tessera** is built to fail closed: when it cannot evaluate a condition, the condition counts against allowing, and missing data never turns a denial into an allow unless the configuration says so. This page lists what tessera does in each situation that it handles, and the key or the rule that changes it.

| Situation | What tessera does | How to change it |
| --- | --- | --- |
| No rule decides the request | It applies [`policy.default_action`](./configuration.md#policy-default-action). | The key is required: every configuration states it. |
| The client address is not available | Every condition whose result depends on `client.ip`, `geo` or `asn` is indeterminate, `has(geo.location)` included: a `deny` rule denies, an `allow` rule does not match. [`tessera_rule_evaluation_errors_total`](./metrics.md#tessera-rule-evaluation-errors-total) counts it, with `cause="client_ip_missing"`, and [`evaluation_error`](./logs.md#evaluation-error) reports it. | A rule with `has(client.ip)` before them: see [Handle a missing client address](../guide/policy-rules.md#handle-a-missing-client-address). |
| A header that a condition reads is missing | The condition is indeterminate, as above. | Test the header first: `"x-api-key" in request.headers && …`. |
| An expression fails: a conversion, an overflow, a division by zero | The condition is indeterminate when its result depends on the failure. | Write the condition so that `&&` or `\|\|` decides first: see [Indeterminate conditions](./expressions.md#indeterminate-conditions). |
| An evaluation exceeds the cost limit | It stops, and the condition is indeterminate, also inside `\|\|` or `&&`. | Simplify the condition: see [Limits](./expressions.md#limits). |
| The file of a set is missing, unreadable or invalid at startup, or has more entries than `max_entries` | tessera does not start: it is a configuration error, and `tessera serve` exits with status 2 before it opens a socket. [`tessera config validate`](./cli.md#tessera-config-validate) reports the same error. | Fix the file or the configuration: see [`sets`](./configuration.md#sets). |
| The file of a set disappears or cannot be read after tessera loaded it | tessera keeps the copy it loaded, and checks the file again every [`sets.<name>.refresh`](./configuration.md#sets-name-refresh). [`tessera_set_refreshes_total`](./metrics.md#tessera-set-refreshes-total) counts each check with `result="error"`, and [`set_load_failed`](./logs.md#set-load-failed) reports the failure once. | [`sets.<name>.max_staleness`](./configuration.md#sets-name-max-staleness) limits the age of the copy. |
| The file of a set changes to an invalid value, or to more entries than `max_entries` | tessera rejects the whole file and keeps the copy in use. `tessera_set_refreshes_total` counts each check with `result="rejected"`, and `set_load_failed` reports the failure once. | Fix the file: see [Update the file of a set](../guide/sets.md#update-the-file-of-a-set). |
| The last successful check of the file of a set is older than its `max_staleness` | The set is unavailable, and `contains` on it answers what [`sets.<name>.on_unavailable`](./configuration.md#sets-name-on-unavailable) says. With the default, `fail`, the condition is indeterminate, with the cause `set_unavailable`: a `deny` rule that depends on the set denies, an `allow` rule does not match. [`tessera_set_available`](./metrics.md#tessera-set-available) is `0`, and [`set_unavailable`](./logs.md#set-unavailable) reports it. The next successful check makes the set available again. | `on_unavailable: match` or `on_unavailable: no_match`: see [Choose what an unavailable set answers](../guide/sets.md#choose-what-an-unavailable-set-answers). |
| A database is missing, unreadable, larger than 512 MiB or invalid at startup, or is a database of the other kind, such as an ASN file configured as `enrichment.geo` | tessera does not start: it is a configuration error, and `tessera serve` exits with status 2 before it opens a socket. `tessera config validate` reports the same error. | Fix the file or the configuration: see [`enrichment`](./configuration.md#enrichment). |
| A database disappears or cannot be read after tessera loaded it | tessera keeps the copy it loaded, and checks the file again every [`enrichment.geo.refresh`](./configuration.md#enrichment-geo-refresh) or [`enrichment.asn.refresh`](./configuration.md#enrichment-asn-refresh). [`tessera_enrichment_database_refreshes_total`](./metrics.md#tessera-enrichment-database-refreshes-total) counts each check with `result="error"`, and [`database_load_failed`](./logs.md#database-load-failed) reports the failure once. | Restore the file. [`tessera_enrichment_database_build_timestamp_seconds`](./metrics.md#tessera-enrichment-database-build-timestamp-seconds) tells the age of the copy in use. |
| A database is replaced with a file that is not a valid database, a database of the other kind, or a file larger than 512 MiB | tessera rejects the file and keeps the copy in use. `tessera_enrichment_database_refreshes_total` counts each check with `result="rejected"`, and `database_load_failed` reports the failure once. | Replace the file with a valid database, by renaming it over the file. |
| A database is replaced with a valid one | The next decisions read the new copy, without a restart; the decisions in progress finish with the copy they had. [`database_loaded`](./logs.md#database-loaded) reports it, and `tessera_enrichment_database_build_timestamp_seconds` has its build time. | — |
| The client address is not in a database | `geo.found` or `asn.found` is `false`, the strings are empty, `geo.subdivisions` is an empty list, `asn.number` is `0` and `geo.location` is absent: not an error. A comparison on the country, such as `geo.country.code == "IT"`, is `false`. | A rule on `!geo.found`: see [`geo`](./expressions.md#geo). |
| tessera cannot read the record of the client address in a database: a corrupt record, or fields of other types than in the schema | Every condition whose result depends on `geo` or `asn` is indeterminate, with the cause `database_error`: a `deny` rule denies, an `allow` rule does not match. `tessera_rule_evaluation_errors_total` counts it, and `evaluation_error` reports it. | Replace the database. |
| A condition reads `geo.location` and the record has no location, or an item of `geo.subdivisions` beyond the end of the list | The condition is indeterminate, with the cause `expression`. | Test it first: `has(geo.location) && …`, `size(geo.subdivisions) > 1 && …`, or read the list with `exists`. |
| An upstream header cannot be computed: its expression fails, or gives a value longer than 4096 bytes, with an ASCII control character other than the horizontal tab, or not valid UTF-8 | tessera removes the header, so that the value of the client does not reach the upstream either, and the decision does not change. [`tessera_upstream_header_errors_total`](./metrics.md#tessera-upstream-header-errors-total) counts it with its cause; no log event reports it. | Write the expression so that it cannot fail, such as `has(geo.location) ? … : ""`, and check it with [`tessera eval`](./cli.md#upstream-headers). See [`upstream.headers`](./configuration.md#upstream-headers). |
| A decision field cannot be computed: its expression fails | The field is empty in the [`decision`](./logs.md#decision) event, and nothing counts or reports it. The decision does not change. | Write the expression so that it cannot fail, such as `"x-tag" in request.headers ? request.headers["x-tag"] : ""`. See [`log.decision_fields`](./configuration.md#log-decision-fields). |
| tessera fails inside the evaluation of a condition, of an upstream header or of a decision field | It recovers, and goes on deciding: the condition is indeterminate, the header removed, the field empty. The event [`panic_recovered`](./logs.md#panic-recovered) reports it with its stack. | — |
| tessera fails elsewhere while it handles a call | It recovers, and the call ends with the gRPC status `INTERNAL`, without a decision: Envoy handles it as a call that failed. [`panic_recovered`](./logs.md#panic-recovered) reports it, with an empty `rule`. | Set `failure_mode_allow` to `false`, so that Envoy denies the request: see [What Envoy needs](./grpc-api.md#what-envoy-needs). |
| A rule is in audit mode | The rule never decides; an indeterminate condition does not deny. | [`policy.rules[].mode`](./configuration.md#policy-rules-mode). |
| The policy is in audit mode | Every request is allowed; a denial that is not enforced has `enforced=false` in its [`decision`](./logs.md#decision) event and in [`tessera_decisions_total`](./metrics.md#tessera-decisions-total). | [`policy.mode`](./configuration.md#policy-mode). |
| Standard output is slow or blocked | Decisions never wait for it: a `decision` event that does not fit its queue is dropped and counted. | See [The queue of decision events](./logs.md#the-queue-of-decision-events). |
| Too many concurrent calls on a connection from Envoy | The calls beyond the limit are refused. | [`server.max_concurrent_streams`](./configuration.md#server-max-concurrent-streams). |
| Too many connections from Envoy | The connections beyond the limit are closed at once. | [`server.max_connections`](./configuration.md#server-max-connections). |
| tessera is unreachable, too slow, or answers with an error | Envoy decides, as its `failure_mode_allow` says. | Set it to `false`: see [What Envoy needs](./grpc-api.md#what-envoy-needs). |
